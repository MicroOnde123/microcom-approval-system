## Confirmed discrepancies — do not hide in employee instructions

1. **Stock review position is a release-documentation blocker.** `workflows/models.py:65` rejects any stock review other than the first configured step. `requests_app/services.py:163–168` independently rejects it during approval. `invoicing/services.py:125–129` requires the designated first stock-review evidence. Thus the requested Fiber sequence (Initial, Stock Review, Direction, Finances) cannot be documented as working in this checkout. No workflow or application code was changed. Confirm the intended newer branch/commit or separately authorize implementation before publishing any-step training.
2. **Feature flag differs between normal source and rehearsal.** `config/settings.py:236` sets `MATERIAL_RETURN_NOTE_UI_ENABLED = True`. The isolated settings set it to `False`. Neither was changed. The production value was not inspected and must not be inferred. Older documents saying it is universally disabled are outdated.
3. **Credit schema is not an employee credit lifecycle.** `invoicing/urls.py` exposes no complete credit creation/review/finalization/PDF UI. `invoicing/test_credit_guards.py` expressly labels its evidence schema fixtures, not an application credit lifecycle. Escalation guidance replaces invented screen steps.
4. **Some French screens contain untranslated English text.** The captured stock-review page still displays “Approve, reject, or return this request.” The Django material Admin also includes English model/field labels. Screenshots preserve the actual interface; the manual does not silently relabel those controls. Application translation corrections are outside this documentation task.
5. **Older guides are incomplete for the current milestone.** They describe a generic material exit slip rather than independent first-issued BC/BS references and omit the newer invoice/return/reconciliation/reporting modules. Some older technical notes describe receipt language selectors that the active-language implementation has replaced.
6. **Password-link logging deserves a separate security review.** `accounts/signals.py` prints newly generated password-set links when a new account has an email. An initial fixture attempt rolled back in full because company settings were absent; it also exposed a synthetic reset link in local command output. No link was stored in these manuals/assets. The successful training account uses no email, avoiding that signal output. No real account or production system was involved; the signal itself was not changed.
